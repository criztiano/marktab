# marktab

Chrome extension that replaces the new tab page with a calm start page: a big search box, the user's bookmarks as one row of mini cards (read live from `chrome.bookmarks`), and optional Pins, Review and Open-tabs blocks below.

## Stack & conventions

- **WXT** (v0.20.x) + **React 18** + **TypeScript**, Manifest V3.
- WXT generates `manifest.json` from `wxt.config.ts` + entrypoint folder names. Never write a manifest by hand.
- `browser.*` is auto-imported by WXT (cross-browser, promise-based). Don't import `chrome` directly.
- The whole UI lives in `entrypoints/newtab/` (App.tsx + style.css). Keep it single-entrypoint unless a feature truly needs a background worker.
- Plain CSS with custom properties (no Tailwind). Dark mode via `prefers-color-scheme`. The look follows Eden's Garden: dark surface `#2e2e2e` with zinc text (light mode mirrors it), no hairline borders — edges come from translucent fills (`--fill-1…4`), 12px radius with `corner-shape: superellipse(2)`, rounded-full pill buttons (`.text-button`, quiet by default, `--primary` for the main action, `.button-group` for several), an 11px medium label per block, system-ui font (never bundle Eden's fonts). The `:root` token block in style.css owns colour, fills, type scale (`--text-*`; the centred search pill at `--text-display` is the one large thing), spacing (`--space-*`), radius (`--r-*`), sizes (`--control`, `--search-height`, `--card-*`), motion (`--ease-out`, `--dur-fast`), z-index and `--target` (24px minimum hit size). Focus is one soft ring (`:focus-visible` with `--ring`). Use tokens, never raw literals. Motion is feedback only (`.pressable` press-scale, hover/focus opacity); no entrance animation; a global reduced-motion clamp sits at the end of the file. Hover styles live inside `@media (hover: hover)`.
- Favicons come from Chrome's local cache: `chrome-extension://{id}/_favicon/?pageUrl=...` (requires `favicon` permission). No external favicon services — core bookmark browsing stays request-free.
- **Network:** the only network layer is the optional Garden source (`entrypoints/newtab/feed.ts`), used by Pins (`Pins.tsx`), Garden search (`Search.tsx`) and Review (`Review.tsx`), all against the one configured host with the same auth headers. No host is hardcoded and none is requested at install. Public builds stay dormant until the user sets a base URL in Settings; local builds may bundle a private config but still require an explicit **Enable Pins** click. Both paths grant one host through `optional_host_permissions` (`optional_host_permissions: ['https://*/*','http://localhost/*']` in `wxt.config.ts`). Base URL + token live in `browser.storage.local` (`storage` permission); `loadConfig` migrates the legacy `eden*` keys. Keep all other surfaces request-free. The "Open tabs" panel uses `scripting` plus a runtime grant of `https://*/*` + `http://*/*` (also in `optional_host_permissions`) — no network, but that grant also satisfies Pins' per-host check.

## Commands

- `npm run dev` — Chrome with HMR
- `npm run build` — generic production build to `.output/chrome-mv3/`
- `npm run build:local` — bumps the patch version, then the private unpacked build; reads `~/.config/marktab/local.json` and writes only the generated bundled config
- `npm run compile` — typecheck only (tsc --noEmit)
- `npm run zip` — store-ready zip

## Delivery rules

- Keep `DEFAULT_CONFIG` blank and public/WXT source generic. Never commit a host, token, generated `marktab-local.json`, or required private host permission.
- Local delivery uses `scripts/configure-unpacked.mjs` only after WXT builds. It writes `.output/chrome-mv3/marktab-local.json` mode 0600 but must leave the generated manifest generic (no required `host_permissions`) and never log the key. Chrome grants only the configured host after the user clicks **Enable Pins**.
- `package.json` is the only version source: `BUNDLE_VERSION` imports it, and `npm run build:local` bumps the patch version before every build (so each reload in Chrome shows a new version). Bump minor by hand for bigger releases. The new-tab entrypoint compares the bundle version to runtime manifest metadata and requests at most one runtime reload when cached assets are newer.

## Architecture notes

- `flatten()` in App.tsx walks the bookmark tree and emits one section per folder that directly contains bookmarks. Section title = folder name only (not breadcrumb path — deliberate UX decision).
- `HIDDEN_ROOTS` (Chrome root folder ids: '1' = Bookmarks Bar) suppresses sections for loose bookmarks in those roots; subfolders still render.
- Page, top to bottom: sticky search bar → inline results (only while searching) → `.home` (hidden but still mounted while searching): the bookmarks strip, then `.dashboard`, a 3fr | 2fr grid (Pins | Review + Open tabs) with intrinsic `minmax(min(100%, …), …)` tracks that stacks to one column below 56rem.
- Bookmarks (`Bookmarks.tsx`): every bookmark from the shown sections, in order, as one row of fixed-size small cards (local favicon on top, centred label below, 2-line clamp). Only this row scrolls sideways (`overflow-x: auto`, `overscroll-behavior-x: contain`, hidden scrollbar); a scroll/resize listener sets `data-fade-start`/`data-fade-end` so only an edge with more content fades (mask) to the page surface.
- Bookmark events (onCreated/onRemoved/onChanged/onMoved) trigger a full reload of the tree — fine at bookmark scale, don't prematurely optimize.
- One row anatomy everywhere (`.rows` > `.row`): leading media (`Thumb.tsx`: neutral block + local favicon, covered by a direct public image when present; square 32px for search/tabs, 16:9 96px for Pins), title over muted meta, trailing aside (age, memory) or action (×). The × keeps a 24px box and grows its hit area with `::before` only away from the row link; it shows on hover or `:focus-within` (always on touch). Shared helpers (`faviconUrl`, `displayHost`, `formatAge` via `Intl.RelativeTimeFormat`, `useDelayedFlag` for skeletons after 300 ms) live in `view-helpers.ts`.
- `garden-source.ts` → `useGardenSource(reloadKey)` reports `off` / `needs-access` / `ready` from `loadConfig` + `hasHostAccess`, and re-reads on Settings save and on `permissions.onAdded/onRemoved` (so the Enable Pins click also switches on search and Review). `loadConfig` shares one in-flight read so concurrent blocks migrate once.
- Search (`Search.tsx`): with a `ready` source it is Garden search — debounced 200 ms `GET /api/marktab/search?q=&limit=8` (`fetchGardenSearch`), each new query/retry aborts the previous request (latest wins), and previous rows stay visible while the next answer loads. Each result is an `<a>` to `{baseUrl}{eden_path}` (`edenItemUrl` accepts only rooted same-origin paths); meta is the item's source host, else its type. Otherwise it falls back to the local title/URL filter over the shown bookmarks, as the same result rows. The status line under the input (`role="status"`) names counts, "Searching…", no-match, or the cause (`feedErrorKind`: offline / auth → "Check Settings" / 404 → "not available on this server yet" / server) with a Retry button. Enter opens the first result in the current tab; if Garden is still answering, it opens the first result once the typed query settles.
- Keyboard: arrows move real DOM focus between search and result links (no virtual cursor, no focus trap), Esc clears, typing anywhere outside a text field refocuses search. Match highlighting wraps the first title hit in `<mark>`.
- `Pins.tsx` is a vertical list in the left column. Notes come first, then pin rows (16:9 still, 2-line title, muted host, × unpin). Only a still image renders: a direct public image, else a video's poster (`pinImage`), never a playing video; absent/unsafe/failed media leaves the local-favicon placeholder. Unconfigured with no notes → "Add a note or quote…"; a configured source without `hasHostAccess` shows **Enable Pins** (its click calls `requestHostAccess` before any other async work so Chrome sees the user gesture; denial/cancellation leaves onboarding visible without an error). The feed is stale-while-revalidate: cached Garden pins (`loadCachedItems`) paint instantly, then `fetchQueue` refreshes and re-caches (`saveCachedItems`); a static skeleton shows only if the first answer takes >300 ms; errors name the cause and offer Retry while stale rows stay. Ordinary navigation has no network mutation; only the explicit × unpin calls the compatibility dismiss endpoint. A V2 cache excludes historical queue cards, and config migration/save clears every cache (`CONFIG_MIGRATION_KEYS`).
- Notes/quotes (`notes.ts`): local-only (`pinNotes` in `browser.storage.local`, synced across tabs via `storage.onChanged`), no network. They render as compact highlighter rows (short notes one type step larger); an optional `by` makes a quote (“curly quotes” + em-dash attribution). Hover/focus shows five fluo dots (`NOTE_COLORS`, default lime) that set its highlighter `color`, plus ×. "+ Note" in the Pins header opens an in-list composer (`field-sizing: content` textarea) that stops key propagation so App's search doesn't steal typing/Escape. Optional `notes` in `local.json` seeds storage once (only while the key is absent).
- `Review.tsx` (right column, only with a `ready` source): `GET /api/marktab/review?limit=6` (`fetchReview`) → posts waiting in Eden's Review page. Header link "Open Review (N)" and every row link to `{baseUrl}/review` (no per-post deep link). Rows: title (2-line clamp), muted one-line summary, age. Cached in `feedReviewCacheV1` for instant paint (stale-while-revalidate); skeleton after 300 ms, "Nothing waiting for review." empty state, errors with Retry, 404 → "Review isn't available on this server yet."
- `Tabs.tsx` + `tab-usage.ts` (lowercase `tabs.ts` would clash with `Tabs.tsx` on macOS) render "Open tabs by memory" under Review: the 3 heaviest (`TABS_COLLAPSED`) by default, with an instant "Show all N" / "Show fewer" toggle up to `TAB_LIMIT` (12) http(s) tabs by `performance.memory.usedJSHeapSize`, read per tab via `scripting.executeScript` with a 1.5 s timeout; discarded, non-web and unanswered tabs are skipped. A thin neutral bar under each row shows its share of the heaviest tab. Stable Chrome has no per-tab process memory (`chrome.processes` is dev-channel only), so figures are JS-heap estimates, shared by same-site tabs in one process, and cached by Chrome for up to 20 min. Before the grant it shows a **Show tabs** prompt (request first in the click). Re-measures on tab create/remove/replace/load-complete and on visibility, only while visible. Row click focuses the tab; × closes it optimistically and moves focus to the neighbouring ×.
- Optional `folders` in `~/.config/marktab/local.json` → bundled `marktab-local.json` (`local-config.ts`) limits bookmark sections to those folder names (case-insensitive; falls back to all when none match). Public builds show all folders.
- `Settings.tsx` is the gear-button modal ("Pins source") for the feed base URL + token. Save calls `requestHostAccess` first (within the click gesture — Chrome requires a gesture for `permissions.request`), then `saveConfig`, then tests via `fetchQueue`. App owns a `reloadKey` that keys `<Pins>` so saving re-fetches. Escape/Tab handled by a capture-phase document listener so Escape doesn't also trigger App's search-clear.
